# 性能验证

## 目标

保留 GPUI 原生文本输入和浮点滚动路径，发行版纯 Rust；输入事件不做整库 JSON 序列化和磁盘写入。原生性能指实现路径和可复测的运行结果，不以“纯 Rust”推断全部场景流畅。

## 本次检查

2026-11-18，Windows，本机 Rust 1.100.0 release：

- 发行版编译、格式检查、3 项保存测试、Clippy `--all-targets -D warnings` 通过。
- 正常依赖树未包含 QuickJS、nsh-js、WebView/Wry、Electron 或开发宿主。
- 真实原生窗口已检查 30 万字正反向滚动、末尾中文文本输入/撤销、长短稿切换、宋体到楷体重排、正常退出和重开后的字体记忆；三个测试稿保存后仍为 2,000 / 100,000 / 300,000 字符。

绘制检查中发现上游 `Input::paint_glyphs` 每帧分配全文字形缓冲并提交屏幕外字形。项目的最小后端补丁先裁掉屏幕外行，再构建可见字形缓冲。相同 30 万字符稿、Noto Serif SC 20 DIP、行高 30 DIP、正文宽 500 DIP、默认窗口尺寸、动态山景开启，分别取相邻的 5 个一秒统计窗口：

| Rust + GPUI 路径 | GPUI 报告 FPS | 每帧绘制均值范围 |
|---|---:|---:|
| 上游全文字形提交 | 29–31 | 32.10–34.49 ms |
| 本项目可视行补丁 | 62 | 2.25–2.50 ms |

这是绘制统计，不是输入到屏幕的端到端延迟，也不是 TSX 与 Rust 的直接性能排名。脱离本机、此文稿和窗口状态时不能套用这些数字。[测量摘要](measurements/2026-11-18-native.json) 记录了每个采样窗口和二进制哈希；原始运行日志和测试文稿不进入 Git。

**验证边界：**上述界面操作检查在可视行补丁之前完成。补丁发行版已启动并采集到新的帧统计，但最后的视觉/滚动复核遇到桌面控制 `GetCursorPos` 拒绝访问（0x80070005），尚待恢复普通桌面。真实双指及 IME 组合输入仍需人工复测。此前用户确认最顺的版本是 TSX + GPUI；当前原生客户端沿用其输入和滚动后端，并加入可视行绘制补丁。

## 复测步骤

1. `scripts/build.ps1` 构建 release，`scripts/long-text.ps1` 启动独立测试资料。
2. 使用相同窗口尺寸、DPI、字体、文稿、山景状态和前台状态比较，分别测试 2 千、10 万、30 万字符。
3. 触控板双指慢滑、快速来回滑、抬手惯性；检查是否吞小位移、跳跃或反向迟滞。
4. 在稿件开头、中部、末尾输入中文，检查 IME 候选窗、组合文字、选区和撤销；切换短稿/长稿及字体后再次滚动。
5. 用 `MISTPAPER_FPS=1` 启用 GPUI 帧统计，`RUST_LOG=nsh::fps=info` 可筛出统计。日志中的绘制耗时不等于触控板到屏幕延迟；工具请求到文件保存的时间也不等于按键到字形延迟。
6. 窗口正常关闭后重新打开，核对最新文字和字体；原始合成测试稿无需带入 Git。

`Store` 的测试覆盖快速连续保存后的最新内容、关闭刷新、损坏文件保留和大正文快照的 Arc 共享。它们验证保存行为，不代表真实手势或整机帧率。
